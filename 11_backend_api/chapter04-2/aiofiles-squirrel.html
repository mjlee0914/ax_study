입고 담당 다람쥐

큰 도토리를 통째로 들지 않고 5MB 자루에 나눠 옮긴다람쥐.

  • 메모리 사용을 줄인다
  • 저장 중 다른 요청을 막지 않는다
  • 실패하면 불완전한 파일을 치운다
① 파일 입력: Annotated + UploadFile + File()

사람 말: “file 변수에는 사용자가 올린 파일을 UploadFile 형태로 넣어달람쥐.”

file: Annotated[
    UploadFile,
    File(description="업로드 파일"),
]
② 안전한 파일명과 실제 저장 경로

../../photo.jpg 같은 경로가 와도 photo.jpg만 남기고 ID 번호표를 붙인다.

raw_filename = os.path.basename(file.filename or "unknown")
physical_target_path = (
    MEDIA_STORAGE_DIR / f"seq_{asset_id_sequence}_{raw_filename}"
)

# 결과: storage/image/seq_1_photo.jpg
③ 5MB 청크로 비동기 저장

파일 전체를 한 번에 메모리에 올리지 않고, 빈 조각이 나올 때까지 반복한다.

async with aiofiles.open(physical_target_path, "wb") as disk_file:
    while True:
        chunk = await file.read(1024 * 1024 * 5)
        if not chunk:
            break
        await disk_file.write(chunk)
④ 도메인 객체와 JSON 영수증

저장이 끝나면 파일 정보를 객체로 묶고, 장부에 기록한 뒤 응답 스키마에 맞게 반환한다.

new_asset = MultimediaAsset(
    asset_id=asset_id_sequence,
    filename=raw_filename,
    file_size=physical_target_path.stat().st_size,
    content_type=file.content_type or "application/octet-stream",
)

asset_repository[asset_id_sequence] = new_asset
asset_id_sequence += 1
return new_asset.to_dict()
⑤ 오류가 나면 불완전한 파일 치우기

저장 중 넘어졌다면 반쯤 만들어진 파일을 삭제하고 HTTP 500으로 실패를 알린다.

except Exception as err:
    if physical_target_path.exists():
        os.remove(physical_target_path)

    raise HTTPException(
        status_code=500,
        detail=f"파일 업로드 실패: {err}",
    )
CHUNK DELIVERY

왜 잘게 나눠 옮길까?

12MB 파일을 한 번에 들지 않고 입고할 때는 5MB씩, 출고할 때는 1MB씩 나눈다람쥐.

📦

출고 담당 다람쥐

손님이 ID를 말하면 장부와 실제 창고를 모두 확인한 뒤 1MB씩 배달한다람쥐.

  • GET /assets/1/download
  • 장부가 없으면 404
  • 파일이 없어도 404
① ID로 장부 조회 
asset = asset_repository.get(asset_id)
if not asset:
    raise HTTPException(status_code=404)
② 1MB씩 읽고 yield

yield는 파일 전체가 아니라 지금 읽은 조각 하나를 먼저 전달한다.

async def get_file_chunk(file_path, chunk_size=1024 * 1024):
    async with aiofiles.open(file_path, "rb") as out_file:
        while True:
            chunk = await out_file.read(chunk_size)
            if not chunk:
                break
            yield chunk
③ StreamingResponse로 다운로드

attachment는 브라우저에게 화면 표시보다 다운로드를 우선하라고 알려준다.

headers = {
    "Content-Disposition": f'attachment; filename="{asset.filename}"',
    "Content-Length": str(asset.file_size),
    "Cache-Control": "no-cache",
}

return StreamingResponse(
    get_file_chunk(physical_target_path),
    media_type=asset.content_type,
    headers=headers,
)
⚠️

다람쥐 기억은 서버 재시작과 함께 사라진다

asset_repository는 메모리 장부라서 서버를 다시 켜면 빈 딕셔너리가 된다. 디스크 파일은 남아 있어도 장부에서 ID를 찾지 못해 다운로드가 404가 된다. 실제 서비스라면 이 정보를 데이터베이스에 저장해야 한다람쥐.
